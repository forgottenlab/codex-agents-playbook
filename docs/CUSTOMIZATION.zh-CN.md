# 定制指南

[English](CUSTOMIZATION.md) | [简体中文](CUSTOMIZATION.zh-CN.md)

## 如何选择档位

- 临时实验或很小的任务使用 **minimal**；
- 大多数项目使用 **standard**；
- 当任务连续性、远程操作边界、详细 `.ai` 历史或界面历史恢复确实重要时使用 **strict**。

## 推荐覆盖顺序

```text
公开规则模板
      ↓
本机私有值
      ↓
仓库级 AGENTS.md
      ↓
更深目录的 AGENTS.md
      ↓
当前任务的最新明确指令
```

不要把只适用于某个项目的例外长期写入全局本机规则；它更适合放在对应仓库内。

## 至少检查这些内容

- 工作区路径；
- 面向用户解释时的语言；
- Git 推送与发布策略；
- 远程操作策略；
- `.ai` 结构与历史保留策略；
- 项目必须运行的测试命令；
- 中英文及其他文档同步规则；
- 项目特有的生成目录与敏感文件。

## 让规则能够验证

优先写“运行目标测试并报告具体命令”，而不是抽象地写“务必小心”。重要规则最好都能对应一个真实失败模式或行为验证场景。
